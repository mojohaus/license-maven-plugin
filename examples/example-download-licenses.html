Download Licenses Examples

This page provides examples of how to use the download-licenses goal. By default, the download-licenses goal will attempt to resolve the license of each project dependency. These files will be downloaded to a local directory to be included in the final packaging of the project if desired. The licenses are downloaded based on the url field of the dependency POM.

After downloading the license files, the plugin will create a summary file in XML format which describes the license(s) associated with each dependency. Note that subsequent runs of the plugin will avoid downloading the licenses unless the local file exists or forceDownload is set to true. Licenses downloaded by earlier builds are also reused from a cache, see Caching the Downloaded Licenses Between Builds.

Basic Example

This example shows how to configure the download-licenses goal for basic usage.

<project>
  ...
  <build>
    <plugins>
      <plugin>
        <groupId>org.codehaus.mojo</groupId>
        <artifactId>license-maven-plugin</artifactId>
        <version>2.9.0</version>
        <executions>
          <execution>
            <id>download-licenses</id>
            <goals>
              <goal>download-licenses</goal>
            </goals>
          </execution>
        </executions>
      </plugin>
    </plugins>
    ...
  </build>
  ...
</project>

Next run your build:

mvn package

For the download-licenses goal, licenses will by default be downloaded into the directory target/generated-resources/licenses. This can be configured using the licensesOutputDirectory parameter.

Bundled License Texts

License hosts such as www.gnu.org are asked for the same few documents by many builds. The plugin therefore ships the texts of the common licenses and writes them from there when a dependency points at a URL that serves exactly such a text. No request is sent for these URLs, no matter whether forceDownload is set. The build log says how many licenses were written this way.

The URLs are listed in the table META-INF/licenses/bundled-license-urls.properties inside the plugin. The scheme (http or https), a leading www. and a fragment are ignored; a URL with a query or a port is never matched. A URL is matched after licenseUrlReplacements have been applied, so a replacement that points to your own mirror also keeps the plugin from using a bundled text. A URL that lies below serverUrl, where credentials are sent, is always downloaded.

The useBundledLicenseTexts parameter (-Dlicense.useBundledLicenseTexts) selects which URLs are answered from the plugin:

  • text: the default. URLs that return plain text. The file has the same name as a downloaded text/plain file and holds the document with the URL, apart from the differences listed below.
  • all: also the URLs of HTML pages. The file is a .txt file that contains the license text instead of the page, so its name, content and checksum differ from those of earlier runs. That is why it is off by default.
  • none: every license is downloaded, as in earlier versions of the plugin.

A licenseUrlFileNames entry with a sha1 still means what it says: when the bundled text has another checksum than the one expected, the URL is downloaded.

These URLs return plain text and are answered with the default setting:

  • https://www.gnu.org/licenses/gpl-3.0.txt: GNU GPL 3.0
  • https://www.gnu.org/licenses/lgpl-3.0.txt: GNU LGPL 3.0
  • https://www.gnu.org/licenses/agpl-3.0.txt: GNU AGPL 3.0
  • https://www.gnu.org/licenses/fdl-1.3.txt: GNU FDL 1.3
  • https://www.gnu.org/licenses/gpl-2.0.txt and https://www.gnu.org/licenses/old-licenses/gpl-2.0.txt: GNU GPL 2.0
  • https://www.gnu.org/licenses/lgpl-2.1.txt and https://www.gnu.org/licenses/old-licenses/lgpl-2.1.txt: GNU LGPL 2.1
  • https://www.gnu.org/licenses/old-licenses/gpl-1.0.txt: GNU GPL 1.0
  • https://www.apache.org/licenses/LICENSE-2.0.txt and https://www.apache.org/licenses/LICENSE-2.0: Apache License 2.0
  • https://www.eclipse.org/org/documents/epl-2.0/EPL-2.0.txt: Eclipse Public License 2.0

These URLs return HTML pages and are answered only with all: the pages gpl-3.0.html, lgpl-3.0.html and agpl-3.0.html below https://www.gnu.org/licenses/, gpl-2.0.html and lgpl-2.1.html below https://www.gnu.org/licenses/old-licenses/, https://www.apache.org/licenses/LICENSE-2.0.html, and https://www.eclipse.org/legal/epl-v10.html, epl-v20.html and their https://www.eclipse.org/legal/epl/ counterparts.

The bundled GPL 1.0 and 2.0, LGPL 2.1 and FDL 1.3 differ from the files on www.gnu.org only in the lines where the FSF has since replaced its postal address or an old web address with https://www.gnu.org/licenses/. The bundled Apache License 2.0 differs from the file on www.apache.org only in white space. Other URLs, for example the ones that always point to the latest version of a license, such as https://www.gnu.org/licenses/gpl.txt, and the pages of opensource.org, are not mapped and are downloaded.

Caching the Downloaded Licenses Between Builds

The licenses of a build that starts from a clean checkout, as most CI builds do, would be downloaded again from the license hosts on every run. To spare those hosts, the plugin keeps every text it downloads from an http or https URL in a cache directory that outlives the build. By default the directory is ${settings.localRepository}/.cache/mojohaus-license-maven-plugin, so a CI job that already saves and restores the local Maven repository carries the cache along, and no other configuration is needed.

The cache works as follows:

  • The key is the final URL, after the licenseUrlReplacements were applied. An entry holds the bytes the server sent, so licenseContentSanitizers and the other processing run on a cached text exactly as they do on a downloaded one, and the files in licensesOutputDirectory are the same either way.
  • A text younger than licenseCacheTtlDays (30 by default) is used without a request to the server.
  • An older text is checked with a conditional request (If-None-Match and If-Modified-Since) and replaced only if the server has a newer one. If the server cannot be reached, or answers with 429 or a 5xx status, the older text is used and the plugin logs a warning.
  • Failed downloads are never cached, and neither are file: URLs. Downloads that send the credentials of serverId are not cached either, so that a text behind authentication does not end up in a directory that a CI job may publish.
  • forceDownload ignores the cached texts but stores the new ones. In offline mode the plugin downloads nothing, so it does not read the cache either.
  • Builds may share a cache directory: an entry is written to a temporary file and moved into place in one step.

The plugin logs at info level once per build how many license texts came from the cache and how many were downloaded.

To keep the cache in a different place, for example a directory that a CI system caches on its own, set licenseCacheDirectory. Set useLicenseCache to false to turn the cache off:

<configuration>
  <licenseCacheDirectory>${user.home}/.cache/mojohaus-license-maven-plugin</licenseCacheDirectory>
  <licenseCacheTtlDays>90</licenseCacheTtlDays>
</configuration>

The parameters can also be set on the command line, as -Dlicense.licenseCacheDirectory=..., -Dlicense.licenseCacheTtlDays=... and -Dlicense.useLicenseCache=false.

To share the cache in CI, restore and save ~/.m2/repository/.cache/mojohaus-license-maven-plugin together with the local repository, or point licenseCacheDirectory at a directory your CI caches. The cache may also be filled once and shipped as part of a build image.

Sorting the Report

The dependencies appear in the order they were resolved in, which changes as the dependency tree changes. The orderBy parameter puts them in a fixed order instead:

<configuration>
  <orderBy>dependencyName</orderBy>
</configuration>

The parameter takes one of the following values, and can also be set on the command line as -Dlicense.orderBy=dependencyName:

Value Description
none The order the dependencies were resolved in. The default.
dependencyName The name the dependency gives itself in its POM. Falls back to the artifact id for dependencies without a name, and for every dependency when extendedInfo is off.
dependencyGav The group id, artifact id and version.
licenseName The license. Dependencies with more than one license are ordered by the alphabetically first of them, dependencies without a license come last.
licenseMatch How the license compares against the lists described in Classifying the Licenses, worst first.

Dependencies that compare equal are ordered by group id, artifact id and version, so the report is the same on every run.

orderBy replaces sortByGroupIdAndArtifactId, which is deprecated. The old parameter still works, and still applies when orderBy is left at none.

Classifying the Licenses

Three lists say which licenses have been signed off, which need a second look, and which must not appear at all:

<configuration>
  <forbiddenLicenses>
    <forbiddenLicense>GNU General Public License v3.0</forbiddenLicense>
  </forbiddenLicenses>
  <problematicLicenses>
    <problematicLicense>Eclipse Public License 2.0</problematicLicense>
  </problematicLicenses>
  <okLicenses>
    <okLicense>Apache License 2.0</okLicense>
    <okLicense>MIT License</okLicense>
  </okLicenses>
  <orderBy>licenseMatch</orderBy>
</configuration>

With orderBy set to licenseMatch, the dependencies come out worst first: the forbidden licenses, then the problematic ones, then the approved ones, and last the ones in none of the lists. A dependency offering several licenses is classified by the most worrying of them, so a dependency under either Apache or GPL is not filed away as approved.

Names are matched ignoring case and surrounding whitespace. POMs spell the same license in many ways, so use licenseMerges to bring the spellings of one license together; a name that no list matches is not reported, it simply counts as unclassified.

Manual License Configuration

By default the plugin will look at the POM of each dependency for license information. However, not all POMs have been configured with the correct license information. In these cases, the required license information can be configured manually. By default, the plugin will look for a file called src/license/licenses.xml. This file contains manually configured license information which will be merged with information from the dependency POMs to create the final license report. The location of this file can be configured using the licensesConfigFile parameter. The following is an example license config file.

<?xml version="1.0"?>

<licenseSummary xmlns="http://mojo.codehaus.org/"
  xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
  xsi:schemaLocation="http://mojo.codehaus.org/ licenses.xsd">
  <dependencies>
    <dependency>
      <groupId>com.wutka</groupId>
      <artifactId>dtdparser</artifactId>
      <licenses>
        <license>
          <name>GNU Lesser General Public License</name>
          <url>http://www.gnu.org/licenses/lgpl.txt</url>
          <distribution>repo</distribution>
        </license>
      </licenses>
    </dependency>
    <dependency>
      <groupId>org.slf4j</groupId>
      <artifactId>jcl-over-slf4j</artifactId>
      <licenses>
        <license>
          <name>MIT License</name>
          <url>http://www.opensource.org/licenses/mit-license.php</url>
        </license>
      </licenses>
    </dependency>
  </dependencies>
</licenseSummary>

The generated license report follows the same XML format as the manual license config file.

Using License Texts From Files

A url element of the manual license config file can also point to a file, so that a license text that is not published anywhere is read from the project instead. A relative path is resolved against the base directory of the project, which keeps absolute paths out of the version-controlled configuration:

<license>
  <name>Company internal license</name>
  <url>file:licenses/company-license.html</url>
</license>

file:licenses/company-license.html, file://licenses/company-license.html and file://./licenses/company-license.html are equivalent. An absolute path needs three slashes, as in file:///opt/licenses/company-license.html.

The copy in licensesOutputDirectory takes its extension from the name of the source file, .html in this example, in the same way as a download takes it from the content type; a source file without an extension is saved as .txt.
